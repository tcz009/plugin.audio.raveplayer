Rave Player 3.9.13
- Independent-review hardening (docs/HARDENING.md §9): response bodies are now
  truly wall-clock bounded — read1() plus a per-recv socket timeout — so a
  slow-drip upstream cannot hold Kodi past the 2 s/20 s deadlines.
- Redirects are no longer followed by urllib automatically: each hop must be a
  public http(s) URL, is resolved/validated like playback, and is charged to
  the route budget; chains are capped at 3 hops (loopback/LAN/ftp redirects
  are refused).
- play_all now applies the same public-host guard as play, so hostile Archive
  metadata cannot point Kodi at loopback/LAN; storage nodes must be
  *.archive.org. Host lookups are memoised per route.
- Quadratically-scanned tag stripping in descriptions/titles is now linear with
  bounded input (hostile "<a"*N / "[COLOR"*N input no longer hangs the UI).
- Feed XML supplied as bytes (including UTF-16) is refused, closing the
  entity-marker encoding bypass. Favourites fsync before the atomic rename;
  cache keys are injective for hostile header values; station favicons and
  play thumb/fanart accept only public http(s) URLs.
- Docs/CODE-REVIEW refreshed for 3.9.13. Known residuals: the play-host DNS
  lookup is synchronous (memoised per route); Kodi 22's legacy music "plot"
  InfoTag warning remains (comment is also set).
- Tests: 272 -> 295 (offline).

Rave Player 3.9.12
- "Latest" and "Podcasts & Mixes" now fetch their RSS feeds concurrently in a
  bounded pool (max 5 workers), so one slow or dead feed no longer serialises
  the screen. The 20 s per-route wall clock, per-fetch timeout clamping, cache
  behaviour and per-feed failure isolation are unchanged; the route-budget
  state and the cache write counter are now locked for concurrent workers.
  (Cold "Latest" measured 9.9 s vs 15.5 s serial on the dev network.)
- Playback URL validation now also resolves the host and refuses loopback,
  link-local, private and metadata addresses (127/8, ::1, 169.254/16, 10/8,
  172.16/12, 192.168/16, fc00::/7, IPv4-mapped loopback, mixed public/private
  DNS answers) with a notification and a failed resolve. Kodi `|Header=`
  suffixes are preserved. Note: streams on the user's own LAN/private network
  can no longer be played through the add-on's play route — use Kodi's own
  library/files or the web app for those; documented in docs/HARDENING.md.
- Tests: 259 -> 272 (offline).

Rave Player 3.9.11
- Internal hardening pass (docs/HARDENING.md). No new features; no UX change
  beyond two failure-path notifications.
- No top-level failure can escape the plugin: every route is guarded, an
  unexpected error is logged with its traceback and notified, and Kodi always
  gets a finished directory (or a failed stream resolve) instead of a spinner.
- One wall-clock network budget per plugin invocation (20 s): slow sources are
  skipped and the partial directory is shown with a notification, so a cold
  Latest/Podcasts/radio/legacy screen can no longer block Kodi for minutes.
  Live-radio mirrors get an 8 s per-attempt timeout and a 10 min cache.
- HTTP response bodies and gzip/deflate output are capped at 8 MiB with a
  wall-clock read deadline (memory-exhaustion / slowloris guard).
- Feed XML with internal entity declarations is rejected (billion-laughs
  guard). Feed enclosures and radio streams must be http(s) URLs.
- Archive filenames and storage-node paths are validated/quoted: malformed or
  hostile metadata can no longer escape the item path or inject URL parts.
  Infinite/overflowing duration and size fields are handled instead of
  crashing the route. "Rave Nights" catalogue names containing spaces open
  correctly again (double-encoding fix).
- "Play" resolves http(s) streams only (Kodi header suffixes still work).
- Favourites updates are serialised with an advisory lock, so overlapping
  saves no longer lose entries. Cache entries are pruned by age/count, stale
  temp files removed, oversized entries dropped.
- Third-party titles are stripped of Kodi label markup before display.
- A failed stream resolve no longer clears the user's music queue; it stops
  the current attempt only. The "Latest" cascade remains fixed by the files
  directory + build-time DNB resolution added in 3.9.8.
- Compatibility guard tests for the Python 3.9-3.14 window (Kodi 22 ships
  3.14); docs (CODE-REVIEW/AGENTS) corrected. Tests: 207 -> 259 (offline).

Rave Player 3.0.0 — 2026 rebuild
- Rebuilt for Kodi 21/22 on Python 3. The 2014 code was Python 2 and could not
  run on any current Kodi.
- Removed the dead dependencies: script.module.TheYid.common, urlresolver,
  script.module.simplejson and the bundled HTMLParser/urllib2 imports.
  The add-on now needs nothing beyond Kodi itself.
- Replaced 70 hand-written site scrapers with two maintained sources:
  the Internet Archive for tape packs and sets, and radio-browser.info for
  live stations. Dead fan sites can no longer break the whole add-on.
- New sections: Rave Tape Packs, Jungle, Hardcore, House & Garage,
  Pirate Radio Archive, Drum & Bass Sets, and live radio by genre.
- Archive search built in, with pagination and proper per-tape labels
  ("TAPE 3 - MASTERVIBE" rather than nine identical rows).
- Artwork and metadata on every item: Archive thumbnails, station logos,
  fanart, plot, genre and duration.
- Graceful failure: a dead source shows a notification and leaves the rest
  of the add-on usable.
- Settings for results per page and station limit.
