Rave Player 3.9.59 — conservative cancel safety
- Cancelling a download never deletes a completed download. A cancel stops
  active queued/downloading rows only; a completed same-URL copy stays in
  Downloads, and cancelling a completed row does not delete it. Removing a
  completed duplicate on cancel is deferred (known limitation); use the
  Downloads room's explicit delete.
- The cancel sidecar is cleared only after the queue store write actually
  succeeds, on both the worker finish path and the owner's restart load.
- A stale window snapshot can no longer overwrite newer owner progress or
  resurrect a completed/dismissed row: store writes merge per-row `updated`
  timestamps and persist short-lived removal tombstones. Local cancel/status
  changes carry a newer `updated` and win.
- Window start/cancel refresh the owner's store first, so a stale window does
  not clear an in-flight cancel. Owner drain and queued-cancel retry are
  retained.
- Versions: plugin 3.9.59, screen 3.9.59 (requires plugin 3.9.59); resolver
  1.1.0. Code only: no device run, no push and no tag.

Rave Player 3.9.58 — cancel safety follow-up
- Explicit URL matching is now used only when cancelling a *completed* row;
  cancelling an active duplicate deletes by job identity only, so a different
  job's finished file can never be removed.
- Owner drain, sidecar save-then-clear ordering and window/owner sidecar
  ownership from 3.9.57 are retained.

Rave Player 3.9.57 — cancel/data-integrity fix
- Cancelling a download can no longer delete a successfully completed file for
  another row that shares the same URL. Completed entries are deleted by job
  identity (key) only, never by URL.
- A queued-cancel sidecar is cleared on owner start and terminal load, so a
  later retry of the same key runs normally instead of being cancelled/deleted.
- The screen download queue now uses the lazy plugin modules hook for
  completed-file deletion, so a screen cancel removes its own file/index row.
- The owner persists a cancelled status inferred from the sidecar, so losing
  the sidecar cannot resurrect the row.

Rave Player 3.9.53
- Resolver wiring (Mediafire / Google Drive / Podomatic / Mega). The plugin now
  requires script.module.raveresolver 1.1.0 and resolves a provider page once
  in mode=play: direct Mediafire/Drive/Podomatic results keep their Referer/
  User-Agent headers through Kodi's |Header= suffix, and a Mega result is the

  base with no headers and no AES-CTR ciphertext fallback.

  plugin URLs, then resolved lazily per track. A long collection never resolves
  up front, never queues a raw page or ciphertext, and keeps its absolute

  wrapper.

  direct URL; Mega downloads use the signed stream endpoint. Resolved URLs
  without a filename extension (Drive, Mega) are accepted, with the audio
  Content-Type choosing .mp3 vs .m4a. The 500 MiB file / 2 GiB total / 256 MiB
  free-space / Content-Length integrity checks and the existing source
  allowlists are unchanged.
- Settings: resolver_service_url (LAN/Tailscale base, blank = in-process only),
  resolver_service_token (Bearer, hidden), resolver_service_cookie (session
  fallback, hidden) and resolver_enable_mega (off by default) are in the
  plugin's Configure dialog.
- Quiet failures: resolver errors log only the provider and exception class,
  never the page URL, token, cookie or signed stream. RTP failures stay silent.
- Repo/CI: plugin 3.9.53 depends on module 1.1.0 and screen 3.9.53 requires
  plugin 3.9.53; build-repo still emits four add-ons, and

Rave Player 3.0.0 — 2026 rebuild
- Rebuilt for Kodi 21/22 on Python 3. The 2014 code was Python 2 and could not
  run on any current Kodi.
- Removed the dead dependencies: script.module.TheYid.common, urlresolver,
  script.module.simplejson and the bundled HTMLParser/urllib2 imports.
  The add-on now needs nothing beyond Kodi itself.
- Replaced 70 hand-written site scrapers with two maintained sources:
  the Internet Archive for tape packs and sets, and radio-browser.info for
  live stations. Dead fan sites can no longer break the whole add-on.
- New sections: Rave Tape Packs, Jungle, Hardcore, House & Garage,
  Pirate Radio Archive, Drum & Bass Sets, and live radio by genre.
- Archive search built in, with pagination and proper per-tape labels
  ("TAPE 3 - MASTERVIBE" rather than nine identical rows).
- Artwork and metadata on every item: Archive thumbnails, station logos,
  fanart, plot, genre and duration.
- Graceful failure: a dead source shows a notification and leaves the rest
  of the add-on usable.
- Settings for results per page and station limit.
